MyBatis 早見表(このアプリの実装対応つき)

案件でよく出る書き方を、このアプリのどのファイルに実装してあるかと一緒にまとめています。

0. 全体像

Controller(web/)      … 画面・APIの入口。パラメータを受け取るだけ
   ↓
Service(service/)     … 業務ロジック＋@Transactional(トランザクション境界)
   ↓
Mapper(mapper/)       … インタフェース。実装は MyBatis が自動生成
   ↓
SQL                   … アノテーション or resources/mapper/*.xml
   ↓
DB(H2)

Mapper インタフェースに @Mapper を付けるだけで Spring の Bean になり、 Service にコンストラクタインジェクションできる。実装クラスは書かない。

1. アノテーション方式 ―― ItemMapper.java

@Mapper
public interface ItemMapper {

    @Select("SELECT id, item_code, item_name FROM item WHERE id = #{id}")
    Item findById(Integer id);

    @Insert("INSERT INTO item (item_code, item_name) VALUES (#{itemCode}, #{itemName})")
    @Options(useGeneratedKeys = true, keyProperty = "id")   // 採番されたIDが引数に入る
    int insert(Item item);

    @Select("SELECT ... WHERE category = #{category} AND unit_price >= #{min}")
    List<Item> find(@Param("category") String category, @Param("min") BigDecimal min);
}
  • #{} = プレースホルダ(?)。値は必ずこちら。
  • ${} = 文字列をそのまま埋め込み。ORDER BY のカラム名など限定的に、 必ずホワイトリスト検証したうえで使う(ItemService.SORT_COLUMNS)。
  • 引数が2つ以上なら @Param が必須。
  • 短い SQL・単純CRUD向け。長くなる / 動的SQLが増えるなら XML へ。

2. XML 方式と resultMap ―― StockMapper.xml

<mapper namespace="com.example.scm.mapper.StockMapper">   // ← インタフェースのFQCNと一致必須

  <resultMap id="stockResultMap" type="Stock">
    <id     property="id"       column="id"/>              // 主キーは <id> で
    <result property="quantity" column="quantity"/>
    <association property="item" javaType="Item"
                 resultMap="itemResultMap" columnPrefix="i_"/>  // 多対一(1件)
  </resultMap>

  <select id="findAll" resultMap="stockResultMap">
    SELECT s.id, s.quantity, i.item_code AS i_item_code ...
    FROM stock s INNER JOIN item i ON i.id = s.item_id
  </select>
</mapper>
  • columnPrefix で JOIN 時の列名衝突を回避。入れ子になると プレフィックスは連結される(d_ + i_ = d_i_)。
  • カラム名とプロパティ名がスネーク↔キャメルの対応なら map-underscore-to-camel-case: true(application.yml)で自動マッピングされる。
  • よくあるエラー Invalid bound statement (not found) の原因は ①namespace 不一致 ②メソッド名と id の不一致 ③XML が classpath に無い、のいずれか。

3. 1対多(collection) ―― ShipmentMapper.xml

<resultMap id="shipmentWithDetailsResultMap" type="Shipment">
  <id     property="id"         column="id"/>
  <result property="shipmentNo" column="shipment_no"/>
  <collection property="details" ofType="ShipmentDetail"
              resultMap="shipmentDetailResultMap" columnPrefix="d_"/>
</resultMap>

JOIN するとヘッダ行が明細数だけ重複して返るが、MyBatis が <id> を キーにして1つのオブジェクトへまとめてくれる。<id> の書き忘れが定番の不具合。

別解として「明細を別SELECTで取る」書き方(select=属性)もあるが、 件数分クエリが飛ぶ(N+1問題)。一覧で使うと性能問題になりやすいので、原則 JOIN で1回にまとめる。

4. 動的SQL

<where>                                     // 条件0件ならWHEREごと消える／先頭のANDも消える
  <if test="criteria.keyword != null">
    AND item_name LIKE '%' || #{criteria.keyword} || '%'
  </if>
  <if test="criteria.statuses != null and criteria.statuses.size() > 0">
    AND status IN
    <foreach item="st" collection="criteria.statuses"
             open="(" separator="," close=")">#{st}</foreach>
  </if>
  <choose>                                  // if / else if 相当。最初に当たった1つだけ
    <when test="from != null and to != null"> AND ship_date BETWEEN #{from} AND #{to} </when>
    <when test="from != null">                AND ship_date &gt;= #{from} </when>
    <otherwise/>
  </choose>
</where>

<set>                                       // UPDATE用。末尾のカンマを落としてくれる
  <if test="itemName != null">item_name = #{itemName},</if>
</set>
  • XML なので < は &lt; に書き換える(> はそのままでも可)。
  • アノテーションでも <script>...</script> で囲めば同じ文法が使える (ItemMapper#search)。

5. まとめ INSERT(foreach)

<insert id="insertDetails">
  INSERT INTO shipment_detail (shipment_id, item_id, quantity)
  VALUES
  <foreach item="d" collection="details" separator=",">
    (#{shipmentId}, #{d.itemId}, #{d.quantity})
  </foreach>
</insert>

1件ずつ INSERT をループするより往復回数が減る。件数が非常に多い場合は ExecutorType.BATCH を使う方法もある。

6. 区分値 ⇔ enum(TypeHandler) ―― ShipmentStatusTypeHandler.java

@MappedTypes(ShipmentStatus.class)
public class ShipmentStatusTypeHandler extends BaseTypeHandler<ShipmentStatus> {
    public void setNonNullParameter(PreparedStatement ps, int i, ShipmentStatus s, JdbcType t) {
        ps.setString(i, s.getCode());          // Java → DB ("20")
    }
    public ShipmentStatus getNullableResult(ResultSet rs, String column) {
        return ShipmentStatus.fromCode(rs.getString(column));   // DB → Java
    }
}

application.yml の mybatis.type-handlers-package に置けば自動登録され、 XML 側に typeHandler= を書かなくても効く。 レガシーDBの区分値カラムを扱うときの定番。

7. トランザクション ―― ShipmentService#allocate

@Transactional
public Shipment allocate(Integer id) {
    Shipment shipment = findById(id);
    for (ShipmentDetail d : shipment.getDetails()) {
        int updated = stockMapper.decrease(d.getItemId(), shipment.getWarehouseId(), d.getQuantity());
        if (updated == 0) {
            throw new BusinessException("在庫が不足しています");  // ← ここで全部ロールバック
        }
    }
    shipmentMapper.updateStatus(id, ShipmentStatus.ALLOCATED);
    return shipment;
}
  • UPDATE ... WHERE quantity >= #{quantity} にして 更新件数0 = 在庫不足と判定する。SELECTしてからUPDATEするより競合に強い。
  • RuntimeException でロールバック。検査例外(Exception)ではロールバックされない点に注意 (必要なら @Transactional(rollbackFor = Exception.class))。
  • 同一クラス内のメソッドを this 経由で呼ぶと @Transactional が効かない(自己呼び出し問題)。

9. デバッグの勘所

  • 発行SQLを見る: logging.level.com.example.scm.mapper: debug(Mapperのパッケージ単位で出せる)
  • データを直接見る: H2 コンソール (JDBC URL は application.yml と同じ jdbc:h2:file:./data/scmdb;AUTO_SERVER=TRUE;DB_CLOSE_DELAY=-1、User sa、Password 空)
  • マッピングされない: カラム別名とプロパティ名を突き合わせる。map-underscore-to-camel-case の有無も確認
  • 明細が1件しか入らない / 重複する: resultMap の <id> を確認
