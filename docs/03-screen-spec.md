## 3.2 共通仕様

### 共通レイアウト

`templates/fragments/common.html` のフラグメントを各画面から差し込む。

| フラグメント | 内容 |
|---|---|
| `head(pageTitle)` | メタ情報、CSS、jQuery、`app.js` の読み込み |
| `header(active)` | ヘッダとグローバルナビ。`active` で現在地をハイライト |
| `messages` | 処理結果メッセージ(緑)、エラーメッセージ(赤)の表示領域 |

グローバルナビ: ダッシュボード / 商品マスタ / 在庫照会 / 出荷指示 / MyBatis早見表 / H2コンソール

### メッセージ表示

| 種別 | 変数名 | 表示 | 設定方法 |
|---|---|---|---|
| 正常メッセージ | `message` | 緑帯 | `RedirectAttributes#addFlashAttribute` |
| エラーメッセージ | `errorMessage` | 赤帯 | 同上、または `Model` に直接設定 |

### 入力チェックの表示

Bean Validation のエラーは、各入力項目の直下に赤字で表示する(`th:errors`)。
エラー時は画面遷移せず、入力値を保持したままフォームを再表示する。

### 例外処理

| 発生箇所 | ハンドラ | 表示 |
|---|---|---|
| 画面用 Controller | `GlobalExceptionHandler` | エラー画面(SC-10)に `errorMessage` を表示 |
| API Controller | `ApiExceptionHandler` | JSON(HTTP 400/500)を返し、jQuery 側で画面に表示 |

| 項目 | ID | 型 | 必須 | 備考 |

## 3.5 SC-03 / SC-04 商品登録・編集

### 入力項目

| 項目 | プロパティ | 型 | 必須 | 入力チェック |
|---|---|---|---|---|
| 商品コード | `itemCode` | テキスト | ○ | 必須。全商品で一意 |
| 商品名 | `itemName` | テキスト | ○ | 必須 |
| カテゴリ | `category` | テキスト(datalist) | ○ | 必須。既存カテゴリを候補表示 |
| 単価 | `unitPrice` | 数値 | ○ | 必須。0以上 |
| 安全在庫 | `safetyStock` | 数値 | ○ | 必須。0以上 |

### イベント

| 操作 | 動作 |
|---|---|
| 登録する / 更新する | 入力チェック→OK なら保存し、SC-02 へリダイレクト(成功メッセージ表示) |
| 入力チェックNG | 同画面を再表示し、項目ごとにエラーメッセージを表示 |
| 商品コード重複 | 同画面を再表示し、画面上部に赤帯でエラー表示 |
| キャンセル | SC-02 へ遷移 |

- 画面タイトル・ボタン名は `mode`(`create` / `edit`)で切り替える。

## 3.6 SC-05 在庫照会

### 絞り込み

| 項目 | ID | 内容 |
|---|---|---|
| 倉庫 | `warehouseFilter` | 倉庫プルダウン。既定は「(すべて)」。変更時に即時再検索 |
| 再読込ボタン | `btnReload` | 現在の条件で再取得 |

### 入庫登録

| 項目 | ID | 必須 | 備考 |
|---|---|---|---|
| 商品 | `receiveItem` | ○ | 全商品を「商品コード 商品名」で表示 |
| 入庫先倉庫 | `receiveWarehouse` | ○ | 全倉庫 |
| 数量 | `receiveQty` | ○ | 1以上。既定値 10 |
| 入庫するボタン | `btnReceive` | ― | `POST /api/stocks/receive` を実行 |

### 一覧項目

倉庫 / 商品コード / 商品名 / カテゴリ / 在庫数 / 安全在庫 / 更新日時(`yyyy/MM/dd HH:mm`)

- 在庫数が安全在庫を下回る行は、在庫数を赤字・太字で表示する。

### イベント

| 操作 | 動作 |
|---|---|
| 初期表示 | サーバサイドで全倉庫の在庫をレンダリング |
| 倉庫変更 / 再読込 | `GET /api/stocks` で取得し、`tbody` を差し替え |
| 入庫する | Ajax で入庫→返却された在庫一覧で `tbody` を差し替え、倉庫フィルタを入庫先に合わせる |
| 入庫成功 | 「入庫しました(数量 N)。UPDATE stock SET quantity = quantity + ? が実行されています。」を表示 |
| 入庫失敗 | API の `message` をそのまま表示 |

## 3.7 SC-06 出荷指示一覧

### 検索条件(GET パラメータとして送信)

| 項目 | プロパティ | 型 | 備考 |
|---|---|---|---|
| 出荷先 | `customerName` | テキスト | 部分一致(大文字小文字を区別しない) |
| 出荷元倉庫 | `warehouseId` | プルダウン | 既定は「(すべて)」 |
| 出荷日 From | `shipDateFrom` | 日付 | ― |
| 出荷日 To | `shipDateTo` | 日付 | ― |
| ステータス | `statuses` | チェックボックス(複数可) | 登録済 / 引当済 / 出荷済 / 取消。IN 句になる |

- 出荷日は From/To の指定有無で条件が切り替わる(両方→BETWEEN、片方→以上/以下、なし→条件なし)。

### 一覧項目

出荷番号(詳細へのリンク) / 出荷先 / 出荷元倉庫 / 出荷予定日(`yyyy/MM/dd`) / ステータス(バッジ) / 操作(詳細)

- 並び順: 出荷予定日の降順 → ID の降順
- 0件時は「該当する出荷指示がありません。」を表示

### ステータスバッジの表示

| ステータス | コード | 表示 | スタイル |
|---|---|---|---|
| 登録済 | 10 | 登録済 | グレー |
| 引当済 | 20 | 引当済 | オレンジ |
| 出荷済 | 30 | 出荷済 | グリーン |
| 取消 | 90 | 取消 | 取り消し線つきグレー |

## 3.8 SC-07 出荷指示登録

### ヘッダ入力項目

| 項目 | プロパティ | 型 | 必須 | 入力チェック |
|---|---|---|---|---|
| 出荷先 | `customerName` | テキスト | ○ | 必須 |
| 出荷元倉庫 | `warehouseId` | プルダウン | ○ | 必須 |
| 出荷予定日 | `shipDate` | 日付 | ○ | 必須。初期値は当日 |
| 備考 | `remarks` | テキスト | ― | ― |

### 明細入力項目(可変行)

| 項目 | プロパティ | 型 | 必須 | 入力チェック |
|---|---|---|---|---|
| 商品 | `details[n].itemId` | プルダウン | ○ | 必須 |
| 数量 | `details[n].quantity` | 数値 | ○ | 必須。1以上 |

### イベント

| 操作 | 動作 |
|---|---|
| 初期表示 | 明細が0行の場合、jQuery が1行を自動追加 |
| ＋明細を追加 | `script[type=text/template]` のひな形の `__INDEX__` を採番して行を追加 |
| 削除ボタン | 該当行を削除し、**残った行の添字を振り直す**(`details[0]`, `details[1]`, ...) |
| 登録する | 入力チェック→OK なら登録し、SC-08 へリダイレクト |
| 入力チェックNG | 同画面を再表示(入力済みの明細行も復元) |
| キャンセル | SC-06 へ遷移 |

> 添字の振り直しを行わないと、Spring のリストバインドで歯抜けの添字となり不正な明細が生成されるため、
> 行削除時の再採番は必須の処理。

## 3.9 SC-08 出荷指示詳細

### 表示項目

| 区分 | 項目 |
|---|---|
| ヘッダ | 出荷番号 / 出荷先 / 出荷元倉庫 / 出荷予定日 / ステータス / 備考 / 登録日時 |
| 明細 | 商品コード / 商品名 / カテゴリ / 単価 / 数量 / 金額(単価×数量) |
| 明細見出し | 合計数量 |

### 操作

| ボタン | 処理 | 方式 |
|---|---|---|
| 在庫引当(Ajax) | `POST /api/shipments/{id}/allocate` | Ajax。成功時はステータスバッジを書き換え |
| 出荷確定(Ajax) | `POST /api/shipments/{id}/ship` | 同上 |
| 取消(Ajax) | `POST /api/shipments/{id}/cancel` | 同上 |
| 引当(POST) | `POST /shipments/{id}/allocate` | 通常のフォーム POST。画面遷移あり(学習用に併記) |
| 削除 | `POST /shipments/{id}/delete` | `confirm` 確認後に削除し、SC-06 へ遷移。**出荷済の場合はエラー**となり、本画面にエラーメッセージを表示して留まる |
| この出荷指示の JSON を見る | `GET /api/shipments/{id}` | 別タブで JSON を表示 |

- Ajax 実行時のメッセージは画面上部の専用領域(`#ajaxOk` / `#ajaxError`)に表示する。
- 業務エラー(在庫不足など)は API が返す `message` をそのまま表示する。

## 3.12 クライアントサイド(jQuery)

`static/js/app.js` に全画面分の処理をまとめている。
画面固有の要素(`#itemTable` など)の有無で、実行する処理を判定する。

| 処理 | 対象画面 | 呼び出す API |
|---|---|---|
| 商品検索 | SC-02 | `GET /api/items` |
| 在庫一覧の絞り込み | SC-05 | `GET /api/stocks` |
| 入庫 | SC-05 | `POST /api/stocks/receive` |
| 出荷ステータス操作 | SC-08 | `POST /api/shipments/{id}/{action}` |
| 明細行の追加・削除 | SC-07 | (クライアント処理のみ) |

### 共通処理

| 関数 | 役割 |
|---|---|
| `comma(value)` | 数値をカンマ区切りに整形 |
| `escapeHtml(value)` | DB 由来の文字列を HTML エスケープ(XSS 対策) |
| `apiMessage(xhr, fallback)` | エラーレスポンスの JSON から `message` を取り出す |
